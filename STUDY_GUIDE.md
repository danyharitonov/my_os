# Как разобраться в my_os перед защитой

Этот файл — шпаргалка: что лежит в проекте, как это работает и что спросит
преподаватель. Прочитай его сверху вниз, параллельно открывая файлы в VS Code.

## 1. Идея за одну минуту

Это «игрушечная» ОС. Настоящего железа нет, вместо диска — база SQLite
`db/os.sqlite`. Главное правило архитектуры: **оболочка не трогает базу
сама**. Путь любой команды:

```
shell.py  →  syscalls.py  →  kernel.py  →  scheduler/memory/fs/auth  →  db.py
(ввод)       (журнал)        (проверка прав)   (работа)                 (SQLite)
```

Моя тема — **планирование процессов**. Поэтому самое интересное лежит в
`scheduler.py`.

## 2. Пройди по файлам в таком порядке

1. `config.py` — все числа: лимит 10 процессов, 4096 КБ памяти, квант 2 такта.
2. `db.py` — `get_connection()` (одно соединение на всю программу) и
   `init_db()` (создаёт 4 таблицы: users, processes, files, syscalls_log).
3. `auth.py` — `check_credentials()` сравнивает SHA-256 от введённого
   пароля с хэшем в базе. `may_modify()` — «владелец или админ».
4. `fs.py` и `memory.py` — простые функции над таблицами.
5. `scheduler.py` — класс `Scheduler`:
   - `queues` — 4 очереди (deque), индекс = приоритет, 3 — самый высокий;
   - `tick()` — один такт: если квант кончился, текущий процесс уходит в конец
     своей очереди, а из самой высокой непустой очереди берётся следующий;
   - `_age()` — старение: кто прождал 4 такта, поднимается на уровень выше,
     поэтому низкоприоритетный процесс не «голодает».
6. `kernel.py` — класс `Kernel`: хранит, кто вошёл (`user`, `role`), проверяет
   права и бросает `KernelError`, если нельзя.
7. `syscalls.py` — все `sys_*`. Декоратор `@syscall` делает три вещи:
   пишет строку в `syscalls_log`, ловит ошибки (ядро не падает), прячет пароль.
8. `shell.py` — словарь `COMMANDS`: имя команды → функция-обработчик.

## 3. Что показать на защите (5 минут)

```bash
python -m unittest discover -s tests -v     # 30 тестов OK
python -m src.shell
login root          (пароль root123)
run compiler 3 512
run backup 0 128
tick 16             # видно, что backup всё-таки получил процессор — это aging
ps
logs 5
```

Потом открой `db/os.sqlite` в SQLite Viewer → таблица `syscalls_log`.

## 4. Вероятные вопросы и короткие ответы

- **Что такое системный вызов?** Запрос программы к ядру; у нас это функция
  `sys_*` в `syscalls.py`, через которую оболочка просит ядро что-то сделать.
- **Почему монолитное ядро?** Все подсистемы в одном процессе Python и
  вызывают друг друга напрямую — проще и нагляднее.
- **Как работает Round Robin?** Процессы по очереди получают квант (2 такта);
  кто не успел — в конец очереди.
- **Зачем приоритеты и aging?** Важные процессы идут первыми, а старение
  поднимает приоритет тем, кто долго ждёт, чтобы никто не ждал вечно.
- **Как хранятся пароли?** Только SHA-256, в журнале вместо пароля `***`.
- **Что будет при нехватке памяти?** `sys_exec`/`sys_mem_alloc` вернут −1,
  в журнале статус `denied`.
- **Почему стрелки на диаграмме только вниз?** Нижний слой не знает о верхнем,
  поэтому, например, базу можно заменить, не трогая оболочку.
- **Нефункциональное требование — это?** Не «что делает», а «насколько
  хорошо»: например, вызов ≤ 50 мс (проверяет `test_syscall_time_budget`).

## 5. Если попросят что-то поменять на месте

- Изменить квант → `QUANTUM_TICKS` в `config.py`, запустить `tick` снова.
- Добавить команду → функция `cmd_xxx` в `shell.py` + строка в `COMMANDS`.
- Добавить вызов → функция с `@syscall(fail=...)` в `syscalls.py`.
